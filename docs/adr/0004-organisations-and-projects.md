# Group projects into organisations

An installation contains organisations, and each organisation contains multiple projects. A project is the existing tracked website/reporting destination, including its domain aliases; preserve existing event history and tracking identifiers when introducing this hierarchy. Organisations provide a combined traffic overview and project drilldowns, replacing an unstructured client-group label.

Keep installation-wide Administrator/Viewer access: organisation selection scopes reports but creates no separate membership boundary. Combined visitor figures sum project-level daily uniques and must not imply people are deduplicated across projects. Aggregate rates from their numerators and denominators, and define a consistent timezone policy for organisation reporting.

## Reporting and migration decision

Organisation reports use UTC event timestamps, with inclusive start dates and an exclusive next-midnight end. This avoids summing incompatible project-local hourly/day buckets, particularly across daylight-saving boundaries. Existing project reports retain their configured local timezone. Their drilldown URLs carry the selected calendar dates and filters; the organisation home explains that date-edge totals may differ.

Project visitor-days count distinct (project, stored local day, visitor identity) within the UTC event window. The organisation total sums project counts; no cross-project or cross-day people deduplication is claimed. Daily bucket visitor counts are local identities observed within each UTC day, so a local visitor-day spanning UTC midnight can appear in adjacent buckets. The initial chart shows additive pageviews, not these non-additive visitor counts. Ranked contribution shares divide each project's pageviews by organisation pageviews; no percentages are averaged. Visit-start-scoped UTC bounce and visible-duration summaries now accompany these traffic figures; ADR 0003 defines their weighted numerators, coverage and boundaries. Goal rates remain planned.

The additive migration creates a default organisation and adds a non-null defaulted grouping column to existing sites. Integrity triggers enforce valid organisation assignments and immutable organisation IDs without rebuilding sites/events: SQLite cannot add a non-null referenced column with a non-null default to populated tables. The default remains available for older clients that omit organisation selection. Existing site endpoints and tracker IDs continue to work. Organisations cannot be deleted through the API. Projects with event history reject deletion; empty projects can still be removed. Moves reattribute all history to the current organisation, rather than retaining a historical membership timeline. Installation-wide roles remain unchanged.
